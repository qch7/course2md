# 计算节点

转写、画面、校对与整理都可以交给其它电脑完成，例如 Hub 跑在没有显卡的服务器上，转写由个人电脑承担。
节点主动连接 Hub，不需要公网地址或开放端口；下载的视频留在节点上，只回传转写、截图与笔记。

## 网状互联与网页内托管

计算服务采用网状结构：一台运行 `course2md web`（或服务器形态由管理员管理）的机器**既是 Hub**（可接收其它节点连入），**也可以同时作为计算节点连入多个外部 Hub**，对外提供转写、画面与整理能力。

- **`.env` 自动连入**：只要本地 `.env` 或环境变量中同时配置了 `COURSE2MD_HUB_URL` 与 `COURSE2MD_WORKER_TOKEN`，启动本地网页服务（`course2md web` / `start.cmd`）时会自动导入并直接连接该外部 Hub，无需另开命令行启动 `course2md worker`。
- **多 Hub 同时接入**：在网页「计算服务 → 连出到外部 Hub」中可继续添加多个外部 Hub，支持直接粘贴 `course2md worker --hub ... --token ...` 命令自动拆分填入，实时查看在线/执行中/重连中/令牌失效状态与节点日志。
- **显存与执行互斥**：本机内置节点与所有对外 Hub 连接共享同一把执行互斥锁与已加载模型缓存，本地任务与外部任务自动排队，避免重复加载 Whisper 模型导致显存溢出。
- **权限边界**：本地模式全部开放；服务器形态下只有管理员可以管理对外连接的 Hub，普通用户不可见也不可调用 `/api/v1/hub-links`。

## 拓扑图与本机节点

「计算服务」页顶部是以本机 Hub 为中心的拓扑图，四类对象用颜色和形状区分：

| 对象 | 颜色与形状 | 含义 |
|---|---|---|
| 本机 Hub | 陶土色圆（居中） | 调度中心，保存课程与笔记 |
| 本机节点 | 绿色圆角方块（左侧） | 与 Hub 同进程运行的节点 |
| 连入的节点 | 蓝色圆（下方） | 其它电脑上主动连入本机 Hub 的节点 |
| 外部 Hub | 紫色菱形（右侧） | 本机作为计算节点连入的其它 Hub |

节点右上角的圆点表示状态（在线、执行中、连接中、异常、离线），虚线表示离线，流动的线表示正在执行任务。
点击任意对象会弹出详情：地址、编号、版本、最近在线时间、执行统计、连接日志，以及按「转写与画面 / 校对与整理 / 来源解析 / 运行位置」分组的能力，并可直接停用、删除、连接或断开。
图中每组末尾的虚线「＋」是新建入口。

**本机节点可以自由创建、修改和停用**（`/api/v1/local-nodes`，仅管理员；纯 Hub 形态没有本机节点）：

- 内置节点（`builtin`）始终存在，可以改名、改能力或停用，不能删除。
- 每个节点可选「自动」（随本机检测结果走，装了新插件或模型后自动获得对应能力）或「自定义」（只承担勾选的能力）。能力只能是本机当前具备能力的子集，一个节点至少要有一项能力。
- 所有本机节点与外部 Hub 连接共享同一把执行互斥锁与模型缓存，所以多个节点只是把能力分开（例如一个只做转写、一个只做整理），不会同时占用显存。
- 服务器形态下本机节点同样不声明 `llm-api`，保持「Hub 上的密钥不会悄悄接走校对与整理」的约定。
- 配置保存在数据目录的 `local-nodes.json`，重启后保留；节点最多 16 个。

## 命令行独立连接

```powershell
# 在 Hub 上生成令牌（也可以在网页「计算服务」中生成）
course2md worker-token --name 我的电脑

# 在节点上连接（令牌也可以放在环境变量 COURSE2MD_WORKER_TOKEN 中）
uv tool install "course2md[asr,cuda]"
course2md worker --hub https://course.example.com --token c2m_xxx --work-dir D:\course2md-worker
```

本地应用自带一个内置节点；局域网内的其它电脑要连接本地应用时，用 `course2md web --host 0.0.0.0` 启动并在
`COURSE2MD_ALLOWED_HOSTS` 中加入访问用的主机名。

## 能力与派发

| 能力 | 含义 |
|---|---|
| `asr` | 已安装 faster-whisper 与 PyAV，可抽音频与转写 |
| `frames` | 已安装 PyAV 与 OpenCV，可扫描画面 |
| `frames:decode` | 已安装 PyAV，可解码视频供筛选器使用 |
| `frame-selector:<名称>` | 可使用对应的画面筛选策略 |
| `llm-api` | 本机已配置 API 密钥，或接口指向本机回环地址（如 Ollama / vLLM），可调用 OpenAI 兼容接口。服务器形态的内置节点（`--with-node`）不声明此能力，由用户连入的节点承担 |
| `agent:dsh` / `agent:codex` | 本机可启动 DSH / Codex |
| `resolver:<名称>` | 已安装对应的来源解析插件 |
| `hub` | 与 Hub 同机运行并共享本地路径（`course2md web` 或 `course2md server --with-node` 启用） |

- **纯 Hub 与计算节点分离**：`course2md server` 默认不启动内置节点（纯 Hub），因此无显卡/无外网权限的服务器绝不会抢占解析、转写或大模型任务；单机带算力服务器可加 `--with-node` 启用本机节点。
- 画面阶段优先在能运行所选筛选策略的转写节点执行。原节点无法抽帧时，具备相应画面能力和来源解析能力的节点可补下载视频并接手。视频已清理时也会补下载，已有转写继续复用。
- 整理阶段需要筛选两张及以上截图时，节点须声明该任务使用的 `frame-selector:<名称>` 能力。
- 本地文件来源仅在存在在线的同机节点（`resolver:local` + `hub`）时可用。
- **服务器上解析来源（列出课次）也由节点完成**：Hub 不直接访问课程平台，因此 Hub 访问不了校内网也不影响使用。
  网页上点击「解析」会派一个很短的「解析课次」任务给具备 `resolver:<名称>` 能力的在线节点（共享节点或你自己的个人节点），
  节点把课次列表传回 Hub。没有符合条件的节点在线时会直接提示需要哪种能力。
  Hub 仍需安装同一个解析插件，用来识别链接属于哪个平台，不会用它发起网络请求。
  本地应用的 Hub 就是你自己的电脑，仍然直接解析。
- 写出转写文件的「输出」阶段声明为 `hub_only`，直接由 Hub 本身写出到输出目录，不需要任何计算节点；整理和后续追问、修改均可交给具备 `agent:*` 或 `llm-api` 的节点，材料、笔记与配图随任务同步。
- **节点产物与缓存生命周期**：节点在每个阶段完成并回传 Hub 后立即清理临时下载的输入与已上传的输出文件（`frames/`、`notes/` 等），只保留本机 `media/` 视频缓存；中间音频 `.wav` 在转写结束、跳过或出错后自动清理（除非开启保留音频）；超期未更新的 `media/` 缓存按 `COURSE2MD_WORKER_CACHE_DAYS`（默认 7 天）自动回收。
- `--without asr` 等参数可以让节点不承担某类任务，`--no-agents` 不承担 DSH / Codex 整理。

节点离线时任务显示「等待具备某能力的节点上线」；节点失联后租约过期，任务自动转交其它节点，多次失联后标记失败。

不同课次独立推进，同一课次的整理与追问按提交顺序执行。Hub 重启后会接回已有阶段任务，节点正常停机则归还当前任务。
开启“完成后清理视频”时，Hub 会向原节点提交后台清理任务；节点离线时等下次上线执行，可在阶段记录中查看状态。

## 停用与删除

在「计算服务」中，外接节点可以停用或删除。停用会立即作废令牌，但保留节点记录；删除会同时移除节点记录，
课程、笔记、历史任务与产物不受影响。删除后需要重新添加节点、生成新令牌才能连接。

内置节点不能通过节点接口停用或删除，请在「本机节点」中编辑或停用它（内置节点本身不可删除）。节点仍有执行中或绑定到它的待执行任务时不能删除，请等待任务结束或取消任务后再操作。
服务器中只有节点主人或管理员可以管理节点。

API `DELETE /api/v1/workers/{worker_id}` 默认仅停用；加上 `?permanent=true` 可永久删除节点记录。

## 服务器上的节点归属

普通用户生成的是**个人节点**，只领取自己的任务；管理员生成的默认是**共享节点**，领取所有人的任务。
课程链接中的凭证只在节点领取任务时解密交给它，个人节点不会收到别人的链接。
